# 风险分析（ISO 14971 思路的工程版）

这份文件按 ISO 14971 的推理顺序写：**危险源 → 危险情况 → 可能的伤害 → 原因 → 控制措施 → 验证 → 剩余风险**。
它不是认证文件：没有临床输入、没有伤害概率量化、没有签核。它的用途是把「我们实际踩到的坑」
转成可追踪的风险条目，并让每条风险都能指回代码与验证记录（与 `docs/traceability.md` 的 `QRS-*` 对应）。

风险等级是工程判断（高/中/低），不是 ISO 14971 的正式风险可接受性判定。

| ID | 危险情况 | 可能的伤害 | 原因 | 控制措施（实现） | 验证 | 剩余风险 |
| --- | --- | --- | --- | --- | --- | --- |
| H-01 | 关键波形（ECG/SpO₂）在窗口被遮挡或后台时延迟数秒 | 医生看到的是过期波形，误判心律/血氧趋势 | QWebChannel 在 macOS 窗口非前台时批量迟发（实测到达中位数 250–325 ms，偶发 >10 s） | 关键波形不进 WebView：原生 `NativeVitalStrip` 直连设备信号绘制与判定（`QRS-N-001`） | 原生 P50 0.24 ms vs 前端 291–367 ms；遮挡场景实测 | 原生条本身的刷新依赖 Qt 事件循环；GPU/窗口服务器异常时仍可能停更（未量化） |
| H-02 | 信号中断但画面继续显示最后一段波形 | 把冻结帧当成实时波形 | 采集线程停止、设备断连 | 每 lane 自带走门狗，超时盖红条「信号中断 XXXX ms · 冻结帧」（`QRS-N-002`） | `QTRS_FAULT=ecg,spo2` 注入，两条 lane 均出现冻结提示 | 阈值（ECG 250 ms / SpO₂ 400 ms）为演示值，未经临床确认 |
| H-03 | 报警被静音后无人注意，或静音状态被遗忘 | 低血氧/心动过缓未被响应 | 静音没有时限、没有留痕 | 静音上限 5 分钟、倒计时可见、到期自动恢复；`alarm.mute`/`alarm.unmute(reason)` 入台账（`QRS-N-004`、`QRS-F-002`） | `QTRS_ALARM_MUTE_SEC=6`：琥珀 → 到期回红，台账成对出现 | 静音是「压提示」，不改变判定；操作者仍可能忽略倒计时 |
| H-04 | 报警优先级不分级，所有报警一个颜色一个节奏 | 高优先级报警被中优先级淹没 | 单档报警 | 两级：高（SpO₂<90 或 HR<50，红）/ 中（SpO₂<92 或 HR<55，黄），级别边沿入台账（`QRS-N-005`） | `QTRS_SIM_SPO2=84/91` 两级截图与 `priority` 字段 | 阈值与分级未按 IEC 60601-1-8 正式定义；无技术报警/生理报警之分 |
| H-05 | 报警声音不符合规范或干脆没有声音 | 手术室内无人察觉报警 | 原实现只有视觉提示，且两级共用系统提示音 | 合成两段可区分的音（高 1000 Hz 三连 / 中 620 Hz 两声），高 3 s、中 8 s 复鸣，静音期间不响，加载失败退回 beep（`QRS-N-006`） | `[Alarm] tone level=2/1 status=Ready` 节流日志；静音期间无 tone 行 | 未按 IEC 60601-1-8 验证声压级、脉冲群与音色编码；音量仍受系统设置影响 |
| H-06 | 设备时钟与宿主时钟存在偏移，延迟显示为负值或数千毫秒 | 医生/工程师误判链路故障，做出错误处置 | 直接相减把时钟差当延迟 | 单侧测量 + 最近窗口最小值估偏移，残差才是延迟（`QRS-T-002`） | `QTRS_CLOCK_OFFSET_MS=5000`：`-4999.81ms` → ECG 229 ms | 偏移估计假设「延迟有下界、偏移短期恒定」；极端网络下界抬高会低估偏移 |
| H-07 | 体积数据经 QWebChannel 传输被截断/破坏 | 重建出的解剖结构与真实不符，误导穿刺/导航 | 文本序列化把 `QByteArray` 变 `String`（2,097,152 → 2,097,145 字符） | 走自定义 scheme 二进制直传 `app://app/__volume/current.bin`（`QRS-T-003`） | 字节数与源一致；`FetchApiAllowed` 缺失时 fetch 直接失败（已验证） | 自定义 scheme 的缓存策略未验证；磁盘错误未覆盖 |
| H-08 | 取回了错误的检查（永远取第一例） | 按错误病人的影像做判断 | 多例时硬编码 `studies.first()` | 多例下拉选择，选择随查询保留（`QRS-I-005`） | 两例库：选第二例 → C-GET 8 对象 → 体积来自该例目录 | 无排序/搜索/患者过滤；同名患者仍可能选错 |
| H-09 | 取回失败或只取回一部分，却按成功处理 | 影像缺层导致结构判断错误 | 仅看 DIMSE 状态、不看落地文件 | `landed < completed` 判「部分失败」；失败按瞬时/确定性分流重试（`QRS-I-002`、`QRS-I-004`） | `--disable-get` 回落 C-MOVE；断网重试验证 | 部分失败的界面提示仍弱；长取回期间心跳互斥（`QRS-I-006`） |
| H-10 | 网络中断长时间不被发现 | 术中调阅影像失败，才发现网络早断了 | 心跳与取回互斥、只在状态翻转时记录 | 心跳独立线程/关联，取回期间照常探测；`pacs.online/offline` 台账（`QRS-I-004`、`QRS-I-006`） | 取回途中杀 PACS：同一秒记 `pacs.offline`，C-MOVE 随后才结束 | 默认心跳 30 s，最坏发现延迟约一个心跳周期；未做秒级重连 |
| H-11 | 进程被杀/崩溃后重启，无人知道上次运行发生了什么 | 重复操作、遗漏事件、误以为数据已保存 | 会话没有闭合标记，内存状态丢失 | `session.end` + 最近会话检测 + `session.recovered` + 体数据来源持久化恢复（`QRS-F-003`） | `kill -9` 重启：`gapSeconds=4`、60 层自动重建；`Cmd+Q` 重启无告警 | 恢复的是「上次显示的那一例」，不是完整工作流状态；未恢复未保存的标注 |
| H-12 | 台账文件被多实例同时写入 / 目录不可写 | 事件时间线缺失或错乱，事后无法复核 | 按天单文件追加，无锁 | 单实例锁（PID 判活，死进程接管）+ 打不开只降级 `qWarning`（`QRS-A-001`、`QRS-A-003`） | 第二个实例 exit 1；伪造死进程锁可接管；正常退出清锁 | 锁只防本机同用户；网络文件系统上的 PID 判活不可靠 |
| H-13 | 演示样例数据覆盖真实取回数据 | 屏幕上显示的是演示脑，被当成病人影像 | 启动自动加载样例 + 取回结果异步到达 | `m_authoritativeVolumeDir` 权威来源标记，样例让位（`QRS-I-002`） | 取回后样例加载被忽略的日志验证 | 若取回失败，界面仍可能停留在样例，需要人看来源 |
| H-15 | 三维体积视图只存在于 WebView，渲染进程被遮挡/异常时停更，且看板无法反映 | 术中定位失去影像参照，操作者不知道画面已经停更 | 体积绘制与滚动列表共用一条合成管线；体积通道没有上屏延迟指标 | 新增原生离屏 OpenGL 绘制路径并排显示（`src/volumeview.cpp`），首帧与稳态耗时入账（`dicom.volumeNativeFrame`） | 遮挡下原生面板仍按 30fps 更新；首帧 241ms、稳态 2.9–7.3ms；暖/冷双色 + 色带图例可区分深度与密度 | 两条路径未做像素级一致性比对；原生侧为等值面渲染，与网页侧观感不同；颜色映射未按临床阅片习惯校准 |
| H-16 | 把自定伪彩当成标准阅片显示 | 颜色被误读为定量信息，窗位不当导致病灶漏看 | 无 HU、无窗预设、无灰阶默认 | 保留 int16 HU + 纹理 R16；CT 窗预设（软组织/骨/血管/自适应）；CT 默认灰阶、非 CT 默认伪彩但均标注「非诊断」；非 CT 数据禁用 HU 预设（`QRS-T-007`） | 合成 CT 体模两档窗预设截图；MR 回退 a.u. 窗日志 | 未做 DICOM PS3.14 GSDF 校准；无医疗显示器；无真实 CT 病灶窗位调优 |
| H-17 | 事件型通道用发布时刻算延迟，看板出现数百秒假值 | 术者误判链路故障，或反过来忽略真实卡顿 | 体积只在加载完成时发一次事件，却被当成持续流 | 体积改用 `parseMs` 单次耗时口径（`recordSpan`）；网页晚挂载用 `lastVolumeTiming()` 补快照；原生接管时前端不挂载 `DicomPanel`，加载由 C++ 触发一次 | 看板 到达 1849 ms / 上屏 273 ms；`QTRS_NATIVE_VOLUME=0` 对照解析仅 1 次 | 体积与报警均已纳入：报警走 `alarmSpan` 单次耗时 + `lastAlarmTiming()` 快照，且不参与中断判定 |
| H-18 | 手动调窗后忘记回到临床预设，用非标准窗位读片 | 病灶在窗边界被截断或低估 | 手势调窗无提示、无恢复入口 | 手动后下拉自动显示「自定义」、状态行常驻 W/L；选回预设即恢复并同步数值；输入框可精确复现 | `QTRS_VOLUME_WL` 与预设 1 两组截图；看门狗不再因体积误报 | 已补「恢复上次预设」按钮与 `⌘⇧W`/物理 `Ctrl+Shift+W`（`QRS-T-015`），窗值/预设/去骨/切面跨重启保留；CT/MR 已按模态分桶，切换模态不再互相夹值 |
| H-19 | 阈值去骨把强化血管一并去掉、切面是空心的被当成真实截面 | 误判血管位置或测量错误 | 纯 HU 阈值、无连通域；切面只跳过样本不封闭 | 去骨仅 CT 启用、勾选框写明 HU≥300；切面只作定位视图，状态栏保留 W/L 与来源；文档明确不能当测量截面 | 骨窗+去骨全黑对照、矢状 50% 截图 | 未做连通域/区域生长去骨，未生成切面盖 |
| H-20 | 台账无限追加写满术中机器磁盘，导致业务日志与状态落盘一起失败 | 术中记录中断、无法事后复核 | 只追加不轮转 | 单文件 8 MB 上限（`QTRS_AUDIT_MAX_MB` 可调），超限改名 `.001` 再开新文件，跨天自动切换；单测覆盖 | 单测：预置 >1MB 文件后 `open()` 断言轮转 | 未做总量上限/旧文件自动清理，需按医院归档策略人工回收 |
| H-21 | Web 渲染进程 RSS 线性增长（≈26–60 MB/min），长时间台次可能耗尽内存 | 术中界面卡死或进程被系统杀掉 | Chromium 原生分配，非 JS 堆；与帧数、重绘方式、消息条数均不相关，只在有数据流进网页时出现 | 已量化并排除 JS 泄漏与绘制路径；实现运行期兜底：默认每 30 分钟换 profile+page 重建渲染进程，实测 3 轮 RSS 均回落到 93 MB、只剩一个渲染进程 | 10 分钟浸泡 + 静音/抽稀/限帧对照 + 3 轮重建实测（`docs/soak-2026-11-06.md`） | 根因仍未定位，但已有可验证的回收手段；`QTRS_RELOAD_MIN=0` 关闭后仍不建议连续运行超过 30 分钟 |
| H-22 | 用固定深色 QSS 覆盖右侧原生面板控件，系统切到高对比度/增强对比度后可能对比不足 | 术中调窗、切面、去骨等关键控件难读，误操作 | QSS 使用固定色值，不跟随系统外观；复选框与下拉箭头曾因样式覆盖短暂不可见 | 只改控件配色，保留系统箭头与文字值；W/L、状态行、图例均保留文本；`VolumeView` 渲染路径未改 | 整窗截图核对下拉箭头/复选框/数值框可见；`npm run typecheck`、`npm run build`、`make cpp`、`ctest`、`make frontend-tests` 均通过 | 未在 macOS 高对比度、色弱或不同显示器色域下验证；未做视觉回归基线；窗口 <700px 时双列波形退回单列 |
| H-14 | 手术室内无外网/无 PACS 时功能不可用 | 术中无法调阅影像 | 依赖在线服务 | PACS 全部本机或院内地址；失败进入未连通态而非崩溃（`QRS-F-004`） | 断连态截图；`--disable-get` 场景 | 未做完整离线模式（本地缓存影像浏览）验证 |

## 尚未做的部分（诚实标注）

- 没有伤害发生概率与严重度的量化评分，因此没有正式的风险可接受性结论。
- 没有临床用户参与的场景梳理（术式、角色、操作时序），风险条目来自工程实现与实测故障。
- 没有 IEC 62304 的软件安全分类（A/B/C）与对应过程裁剪；当前按「有软件故障即可能影响诊断」的保守假设推进。
- 报警相关条目未按 IEC 60601-1-8 做音调、颜色、闪烁频率与延迟的合规验证（`QRS-R-003`）。
